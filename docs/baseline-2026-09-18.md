## Implemented architecture

Python `src/` package; setuptools build; Python >=3.10 declared; official MCP
SDK `mcp>=2.2,<3` is the runtime dependency. Entry points are `hungry-hippa`
and `hungry-hippa-mcp`. Installation uses `python -m pip install -e .`.

SQLite WAL, foreign keys, per-operation connections and reversible migrations
through schema v5. Separate episodes, evidence, beliefs, temporal graph,
procedures, vectors, FTS5, evidence junction tables and audit/maintenance tables.
Controller coordinates importance, provenance, trust, quarantine, supersession,
consolidation and retrieval. Existing architecture is retained.

Retrieval uses FTS5/BM25, optional local Ollama vectors and bounded graph
traversal, then policy filtering, explainable heuristic scoring and a bounded
context compiler. Local embedding failure has a lexical fallback. No evidence
yet justifies replacing this pipeline.

Baseline ingestion: ChatGPT JSON parser and CLI `--dry-run` only. Canonical
dataclasses preserve text, roles, IDs, all branches and the current path. No
released import write/extract pipeline. Parsing is unbounded at this baseline.
Unmerged branches form a linear ingestion prototype stack from `1221b16`
through `06b2a82`; they are not released functionality. This cycle first reuses
the canonical store and CLI commits after review, then hardens raw evidence.

MCP is stdio-only with six tools. CLI supplies observability, quarantine review,
backup/rotation, migration, integrity checks and optional Hippo-Pot lifecycle.
There is no production HTTP API or Control Center. A backup CLI exists, but no
complete managed restore workflow or encrypted backup facility.

## Security and validation

Present: channel-bound identities, owner token, capability checks, quarantine,
verified versus claimed provenance, non-owner supersession restrictions,
injection framing, resource caps, 0600 database/backup creation and mutation log.
Limits: plaintext stores/backups, no same-user process isolation, no
cryptographic audit chain or tenant model. Imported content is untrusted data;
provider metadata is not an attestation. Root SECURITY.md has stale identity
and supported-version statements that need correction.

Existing tests cover acceptance, migration, memory architecture, real SDK MCP,
trust, permissions, provenance, injection framing, supersession, resource
limits, quarantine, parser, packaging, backup and deployment. The local runner
has 21 steps; baseline CI omits the Hippo-Pot suite that the local runner runs.
An isolated venv with Python 3.14.7 and MCP 2.2.0 was installed for verification.
Results are recorded in PROJECT_STATE.md after completion.

`eval/` already contains a ten-scenario synthetic, offline memory challenge
and drift gate. Embeddings and LLM grading are off; token-match recall is not
real-world memory quality. `demo/` uses invented data. Preserve these assets.
Existing documentation includes migration, threat model, security audit,
comparison, MCP, ingestion, release checklist and historical coordination.
No root architecture/roadmap/decision/agent files exist on baseline main.
PROJECT_STATE.md exists on the unmerged stack and will be reconciled, not
treated as an authoritative statement that its branches are merged.
